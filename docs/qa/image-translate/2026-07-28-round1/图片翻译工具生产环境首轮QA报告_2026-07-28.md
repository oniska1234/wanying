## 3. P0 阻断缺陷

### P0-001：生产服务实际使用源码中的硬编码 Qwen 密钥

证据：

- `services/image-translate/config.py` 存在硬编码默认密钥；
- 运行中的 Python 进程没有 `QWEN_API_KEY` 环境变量；
- 服务日志显示 `qwen_disabled=False`；
- 因此当前生产服务实际依赖源码默认密钥。

风险：

- 密钥进入服务器源码、Git 历史、归档或镜像；
- 可能造成未授权调用和费用损失；
- 密钥轮换困难。

立即处理：

1. 轮换现有密钥；
2. 删除源码默认值；
3. 只允许通过环境变量或密钥管理服务注入；
4. 检查 Git 历史、部署包和日志；
5. 查看 DashScope 账单及异常调用。

报告中未记录完整密钥。

### P0-002：HTTPS 页面返回 HTTP OSS 图片地址

任务详情返回：

```text
source_url scheme: http
output_url scheme: http
```

页面 CSP 为：

```text
img-src 'self' data: https:
```

因此 HTTP OSS 图片会被 HTTPS 页面和 CSP 按混合内容阻止，原图/译图缩略图及预览不可正常显示。

单文件下载也返回：

```text
307 → http://openclaw-webste-stock.oss-cn-shanghai.aliyuncs.com/...
```

修复建议：

```ts
new OSS({
  secure: true,
  ...
})
```

并回归：

- 所有签名 URL 必须是 `https://`；
- HTTPS 签名 URL 返回 200；
- 页面无 Mixed Content/CSP 错误；
- 单图下载不会降级到 HTTP。

本轮已验证：将同一签名 URL 的协议改成 HTTPS 后可以正常返回图片，说明 OSS 本身支持 HTTPS。

## 4. P1 功能缺陷

### P1-001：Nginx 默认约 1MB 上传限制

1.8MB 中文图片上传结果：

```text
HTTP 413 Request Entity Too Large
Server: nginx/1.24.0
```

代码允许单次 50 张，但 Nginx 没有配置 `client_max_body_size`。真实 1688 商品图通常可能超过 1MB，当前限制使大量业务图片无法进入应用。

建议：

- 明确单文件上限，例如 10MB；
- 明确单任务总大小，例如 50MB；
- Nginx、Next.js 和业务校验三层保持一致；
- 前端选择文件时提前显示大小错误。

### P1-002：只上传不支持格式会创建永久 processing 任务

上传一个 `.txt`：

```json
{
  "task_id": "...",
  "total": 0,
  "message": "任务已提交"
}
```

数据库任务：

```text
status: processing
total_count: 1
items: []
```

Python 服务：

```text
GET /task/{id} → 404 Task not found
```

原因：

- 后端创建任务后才逐个跳过不支持格式；
- 有效文件为 0 时仍调用 `/process`；
- Python 返回 400，但后端没有检查 `resp.ok`；
- 后端仍将任务标记为 processing。

结果：任务永久停在处理中，刷新和重新登录也无法恢复。

### P1-003：伪造图片先进入 OSS，服务端只在处理阶段失败

纯文本改名 `.jpg`：

```text
上传 HTTP 200
最终 failed 1
OSS 留下输入对象
```

当前只校验扩展名，没有校验：

- MIME；
- 文件签名；
- Pillow/OpenCV 可解码性；
- 单文件大小；
- 像素数量；
- 解码炸弹。

应在创建任务和写入 OSS 前完成文件级校验。

### P1-004：同名文件导致 OSS 覆盖和数据库状态错乱

同一任务上传两个同名 `QA-IMG-DUP.jpg`：

```text
task total: 2
task failed: 2
第一个 item: failed
第二个 item: pending
```

原因：

- 两个输入使用同一个 OSS key；
- 两个结果使用同一个输出文件名；
- 状态同步使用 `fileName` 查找，只更新第一个同名 item。

即使图片有效，也可能出现：

- 输入覆盖；
- 输出覆盖；
- ZIP 重名；
- 一个 item 永久 pending；
- 用户看到错误的原图/结果图配对。

必须使用 item ID/UUID 作为 OSS 文件名和状态关联键。

### P1-005：没有 multipart/form-data 时返回 500

登录用户直接 POST 上传接口且不带 multipart：

```text
HTTP 500
```

应返回结构化 400，例如：

```json
{"error":"请上传图片文件"}
```

### P1-006：合法/非法混合文件造成任务进度不一致

上传 1 个允许扩展名的伪造图片 + 1 个 `.txt`：

```text
API 返回 total: 1
数据库 total_count: 2
最终 status: done
done_count: 0
failed_count: 1
item 数: 1
```

前端进度计算：

```text
(done + failed) / total = 1 / 2 = 50%
```

任务已经“完成”，进度条却只能停在 50%。

所有文件必须在创建任务前一次性验证；要么整个请求拒绝，要么为每一个拒绝文件创建明确 failed item，并保证总数一致。

### P1-007：任务状态只存在 Python 进程内存

微服务使用内存字典保存任务状态。

静态风险：

- PM2 重启后 Python `/task/{id}` 返回 404；
- 数据库任务可能永久停在 processing；
- 多实例无法共享任务；
- 没有失败回收、重试和超时机制。

本轮没有主动重启生产服务，避免影响其他用户。该项需要在修复后的隔离测试环境验证。

## 5. P2 问题

### P2-001：错误信息泄露服务器绝对路径

伪造图片错误包含：

```text
/opt/wanying/services/image-translate/tmp/{task_id}/input/{file}
```

前端用户不需要知道服务器目录。应返回稳定错误码和用户可理解信息，详细堆栈只进入服务器日志。

### P2-002：OSS/历史和日志没有生命周期管理

当前观察：

- OSS Lifecycle 规则数为 0；
- 页面/API 没有删除历史任务能力；
- 失败文件会留在 OSS；
- Python 使用普通 `FileHandler`，未见日志滚动；
- 数据库和 OSS 会持续增长。

如果产品要求永久历史，应至少提供：

- 用户删除；
- 管理员清理；
- 失败/孤儿对象回收；
- 存储用量统计；
- 套餐配额；
- 日志滚动；
- 备份与数据保留说明。

### P2-003：浏览器完整验收被自签名证书阻塞

标准浏览器：

```text
net::ERR_CERT_AUTHORITY_INVALID
```

标准 TLS 校验：

```text
ssl_verify_result: 18
```

本轮不能完成：

- 真实拖拽；
- 文件选择器；
- 页面缩略图；
- 浏览器 Mixed Content 控制台证据；
- 下载拦截体验；
- Chrome/Edge/Safari 响应式。

API 和服务器侧证据不替代可信证书下的最终 UI 验收。
