# MY Profit 生产环境首轮测试报告

- 测试日期：2026-07-27
- 测试环境：Production
- 测试地址：`http://47.106.167.145/tools/my-profit`
- 报告类型：首轮冒烟＋核心计算＋边界＋基础安全
- 测试结论：**不通过，暂不建议对外正式使用**

## 一、结论摘要

生产环境可以访问，注册、登录会话、公开页面、受保护页面、基础利润计算和 360px 移动端布局均可运行。

但是当前发现 3 个 P0 阻断缺陷和 1 个 P1 问题：

1. 生产费率与 2026 年马来站规则不一致；
2. 负数售价等非法业务输入可以进入计算，生成严重误导结果；
3. 生产环境只有 HTTP，账号密码及经营成本未通过 HTTPS 传输；
4. 保存功能使用原生 `prompt()`，当前自动化浏览环境无法完成保存流程。

按照既定上线标准“无未关闭 P0/P1”，当前版本不能判定为验收通过。

## 三、缺陷明细

### BUG-P0-001：生产费率与当前马来站规则不一致

**严重级别：P0**

测试条件：

- 店铺：Marketplace
- BXP：是
- 类目：Electronics
- 商品原价：RM100
- 卖家折扣：RM10
- 买家运费：RM5
- 其余成本及比例：0

生产页面显示：

- 平台佣金：5.00%
- 交易费：2.00%
- 平台支持费：RM1.00/订单
- 规则版本：v1
- 来源：TikTok 官方费率

当前 TikTok Shop 马来站官方资料显示：

- 交易费为 3.78%；
- 平台支持费为 RM0.54/成功交付订单；
- 佣金按子类目、Marketplace/Mall、BXP/非 BXP 区分，不能用一个 Electronics 一级类目固定 5% 代表。

影响：

- 平台费用被错误估计；
- 净利润、保本价和最高采购价全部受影响；
- 页面标记“TikTok 官方费率”会增强错误结果的可信度；
- 可能直接造成选品及定价损失。

建议修复：

1. 停用当前 v1 规则；
2. 导入按官方子类目拆分、带生效日期的规则；
3. 将交易费更新为当前有效口径；
4. 将支持费更新为当前有效金额及适用条件；
5. 无法命中精确子类目时禁止显示“精准利润”；
6. 为每条规则显示官方来源 URL、发布日期和生效时间；
7. 使用真实结算案例回归后再发布。

参考：

- TikTok Shop Malaysia：Commission Fee & Seller Fees Calculations
- TikTok Shop Malaysia：Transaction Fee
- TikTok Shop Malaysia：Platform Support Fee

### BUG-P0-002：负数售价可以进入计算并产生误导结果

**严重级别：P0**

测试步骤：

1. 商品原价输入 `-1`；
2. 卖家折扣保留 `10`；
3. 点击重新计算。

实际结果：

- 总交易额：RM -11.00；
- 单件净利润：RM -32.72；
- 净利率：297.41%；
- 达人＋广告成本：RM -2.02；
- 目标 20% 净利率建议售价：RM53.24；
- 页面正常生成完整计算结果。

问题：

- 商品原价不应小于或等于 0；
- 卖家折扣不应大于商品原价；
- 比例成本的计费基数不得为负；
- 负数利润除以负数交易额得到正净利率，业务含义错误；
- 求解器必须受合法售价下界约束。

建议校验：

```text
商品原价 > 0
0 ≤ 卖家折扣 ≤ 商品原价
0 ≤ 平台折扣
商品数量为正整数
0 ≤ 所有比例 ≤ 100
汇率 > 0
所有成本及费用 ≥ 0
用于比例费的计费基数 ≥ 0
```

前端和服务端必须使用同一套校验；非法输入不得保留旧结果或输出新结果。

### BUG-P0-003：生产环境未启用 HTTPS

**严重级别：P0**

实际：

- 生产地址为 `http://47.106.167.145/...`；
- HEAD 响应未发现 HSTS；
- 用户可以在 HTTP 页面注册和输入密码；
- 用户采购价、成本和利润等敏感经营数据也通过 HTTP 传输。

影响：

- 密码、会话及经营数据存在被窃听或篡改风险；
- 不满足生产环境基本安全要求；
- 无法安全设置完整的 Secure Cookie/HSTS 策略。

建议：

1. 配置正式域名；
2. 申请并部署有效 TLS 证书；
3. HTTP 全量 301/308 跳转 HTTPS；
4. 会话 Cookie 设置 `Secure`、`HttpOnly`、合理的 `SameSite`；
5. 验证 HSTS、CSP、X-Content-Type-Options、Referrer-Policy 等响应头；
6. HTTPS 上线后强制所有登录会话失效并重新登录。

### BUG-P1-001：保存功能依赖原生 prompt()

**严重级别：P1**

点击“保存到选品清单”后，页面调用浏览器原生 `prompt()` 获取信息。在本次自动化浏览环境中产生：

```text
Error: prompt() is not supported.
```

影响：

- 保存流程无法在当前自动化环境执行；
- 难以建立稳定的 E2E 自动化；
- 原生 prompt 缺少结构化校验、字段说明和一致的移动端体验。

建议：

- 改为应用内模态框；
- 字段至少包含商品名称、SKU、商品链接、状态、标签和备注；
- 提供必填校验、取消、保存中、失败重试及成功提示；
- 增加稳定的 `data-testid` 便于自动化。

## 四、计算核对

使用当前生产配置执行标准案例：

```text
商品原价：100
卖家折扣：10
买家支付运费：5
其他成本：0
```

系统当前配置：

```text
佣金 = (100 - 10) × 5% = 4.50
交易费 = (90 + 5) × 2% = 1.90
支持费 = 1.00
平台总费用 = 7.40
净利润 = 95.00 - 7.40 = 87.60
```

结论：

- 算术加总与页面展示一致；
- 业务规则输入错误，因此最终经营结果仍不正确；
- “公式算对”不能抵消“规则用错”。

在卖家折扣 RM10、零商品成本的案例中，系统给出保本售价 RM5.81。该售价低于卖家折扣，导致商品收入为负，说明求解器没有对候选售价施加合法业务约束。
