# TikTok Shop 马来西亚站利润选品工具

## 测试方案与测试数据说明（2026）

- 文档版本：v1.0
- 对应 PRD：TikTok 马来站利润选品工具 PRD v1.0
- 测试对象：响应式 Web 应用
- 测试阶段：开发自测、接口测试、系统测试、回归测试、上线验收
- 测试结论状态：待开发完成后执行

---

## 一、测试目标

验证产品能够在不同店铺身份、类目费率、币种、成本和退款情景下：

1. 匹配正确且在有效期内的费率规则；
2. 准确计算平台费用、总成本、净利润、净利率、保本售价和最高采购价；
3. 保存不可变的计算快照，并在规则更新后提示重新计算；
4. 正确完成多 SKU 比较、选品管理和 CSV 导出；
5. 在移动端和桌面端稳定运行；
6. 在汇率、费率和网络服务异常时安全降级；
7. 确保不同用户之间的数据隔离；
8. 满足上线所需的性能、安全、可用性及可访问性要求。

计算准确性属于最高优先级。任何可能导致卖家错误判断盈亏的问题都作为 P0 缺陷处理。

## 七、缺陷等级

| 等级 | 定义 | 示例 |
|---|---|---|
| P0 阻断 | 造成错误经营决策、资金风险、数据泄露或核心流程不可用 | 净利润算错、匹配错误费率、跨账号读到成本 |

| P3 建议 | 不影响功能的小问题 | 文案、间距、低频交互优化 |

### 9.2 金样公式口径

本测试数据先采用以下确定口径：

```text
卖家商品收入 = 商品原价 - 卖家折扣
卖家订单收入 = 卖家商品收入 + 买家支付运费
平台佣金 = 卖家商品收入 × 佣金率
交易费 = 卖家订单收入 × 交易费率
达人佣金 = 卖家商品收入 × 达人佣金率
广告成本 = 卖家商品收入 × 广告比例 + 广告固定金额
人民币成本折算 = 人民币成本 × CNY_TO_MYR

正常净利润 =
卖家订单收入
- 平台佣金
- 交易费
- 支持费
- 达人佣金
- 广告成本
- 全部 MYR 成本
- 人民币成本折算
```

如开发确认的平台实际口径不同，必须先更新 PRD、公式版本和测试数据，再执行验收，不能只修改程序。

## 十、边界与异常测试数据

### 10.1 数值边界

- 金额：`0`、`0.001`、`0.0049`、`0.005`、`0.01`、`99999999.99`；
- 比例：`0%`、`0.01%`、`99.99%`、`100%`、`100.01%`；
- 汇率：`0`、`-1`、`0.000001`、`0.65`、`999999`；
- 数量：`0`、`1`、`50`、最大整数、负数；
- 文本：空、1 字、最大长度、超过最大长度；
- 日期：闰日、月底、跨年、规则生效边界；
- 时区：吉隆坡 00:00 与上海 00:00 的差异。

### 10.2 恶意及安全数据

```text
<script>alert(1)</script>
' OR 1=1 --
../../etc/passwd
=HYPERLINK("https://example.invalid","click")
@SUM(1+1)
javascript:alert(1)
超长 Unicode、emoji、组合字符、RTL 控制字符
```

预期：

- 页面按文本安全显示；
- 数据库查询参数化；
- CSV 危险首字符被转义；
- URL 协议使用白名单；
- 日志不记录密码、令牌和完整成本数据。

### 10.3 服务异常

- 汇率接口超时、500、429、返回空值和返回负值；
- 数据库短暂断连；
- 缓存不可用；
- 重复提交；
- 网络断开后恢复；
- 费率定时发布任务重复执行；
- 支付回调乱序和重复；
- 两个浏览器同时编辑同一商品。

## 十四、回归测试

2. 运行全部计算金样；
3. 验证新旧生效时间边界；

6. 验证规则来源与版本显示；
7. 生成规则变更测试报告。

每次应用发布：

- 自动执行 P0 单元、API 和 E2E；
- Staging 执行 P0/P1；
- Production 执行只读或最小写入冒烟；
- 失败时禁止自动上线。
